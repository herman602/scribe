# Scribe v0.1.0 release audit

Date: 2026-11-16  
Scope: local evidence, private GitHub staging, and approved public project site;
repository visibility remains private until the final exact-commit gates pass
Runtime baseline: Python 3.14.5, uv 0.10.9, migration `0022`

## Result

The current source completed its private GitHub staging gate, and the user then
explicitly approved public publication. A tracking-free project website is live
at [`scribe-project.andylab.dev`](https://scribe-project.andylab.dev). Repository
visibility remains private and no release tag or GitHub Release exists yet:
the website link in this source must first receive the same exact-commit GitHub
workflow gates. Live Gmail authorization remains excluded on purpose: every
public installation must bring its own Google Desktop OAuth client, and CI must
never depend on a real mailbox.

## Public project website

The public website is a separate static Sites deployment. It contains a
synthetic dashboard image already present in this repository, has no analytics,
trackers, cookies set by project code, external fonts, or browser CDN
dependencies, and links installation and parser-extension documentation back to
this repository. Its source is maintained in a separate Sites repository so the
Python distribution remains focused on the application.

The custom hostname `scribe-project.andylab.dev` uses a DNS-only CNAME plus the
two provider validation TXT records. Cloudflare token status was verified as
active and the credential file mode as `0600` before use. DNS read-back matched
all three requested records, and Sites reported the domain, provider route, and
SSL state as active. An outside HTTPS request returned 200 for both the homepage
and its stylesheet. The existing private application hostname, formal database,
OAuth files, and LaunchAgents were not changed.

## History and secret review

The official Gitleaks 8.30.1 macOS arm64 archive was checked against its
published checksum before execution. The scan shape was:

```text
gitleaks detect --source . --config .gitleaks.toml --redact --verbose --log-opts=--all
```

The private development graph contained 141 reachable commits at the final
pre-audit scan. Gitleaks reported one redacted `generic-api-key` match. Manual
review showed that it was a synthetic ledger idempotency key in a test, not a
credential; the current fixture is operator-neutral.

The same history also contains pre-release author metadata tied to a private
work identity. That metadata is unnecessary for users and must not be
published. Deleting files from the tip would not remove it. The release policy
is therefore:

1. export the verified tracked tree;
2. initialize a new repository with one root commit and a public-safe author;
3. scan every commit in that new repository without `.gitleaksignore` or a
   path allowlist;
4. push only that root and subsequent public-release commits.

A rehearsal root commit containing 375 tracked files was created from the
verified tree. Gitleaks scanned its single commit and approximately 4.90 MB of
content: 0 findings. No raw scan report is stored in the repository.

## Fresh-clone rehearsal

A separate clone of the one-commit candidate contained no ignored files from
the working installation. The following user path was exercised:

| Step | Evidence |
| --- | --- |
| Dependency setup | `uv sync --extra dev` installed the locked environment and built `scribe-local==0.1.0`. |
| Initialization | `python -m app init` created private paths and migrated an empty SQLite database to `0022`. |
| Diagnostics before OAuth | Python, config, data directory, SQLite integrity, and migration checks passed; OAuth credentials/token were the only failures and the network check was skipped. |
| Synthetic OAuth validation | A non-routable fixture Desktop-client document passed shape validation at mode `0600`; token remained intentionally absent. |
| Gmail and parser behavior | 62 mocked full-sync, incremental-sync, bank-parser, and transaction-parsing tests passed. |
| Service generation | 11 integration/CLI tests passed against a fake launchd gateway; no user LaunchAgent was installed. |
| Backup | Online backup reported `revision=0022 integrity=ok foreign_key_violations=0 verified=True`. |
| Restore | Preview wrote nothing; confirmed restore completed at `0022` and retained a rollback copy. |
| Missing-token sync | Failed with the documented authorization instruction and persisted the dashboard warning without creating or exposing a token. |
| Offline dashboard | First-run home, cards, sync, and account pages returned HTTP 200 on loopback. |

The rehearsal caught one documentation defect: the Gmail OAuth guide did not
say that a downloaded `credentials.json` should be mode `0600`, while `doctor`
correctly warned about it. A regression assertion and the missing instruction
were added in commit `44550de`; the synthetic file then passed the credentials
check, leaving only the expected missing-token result.

## Private GitHub staging

The authorized staging repository is
[`herman602/scribe`](https://github.com/herman602/scribe). GitHub's API was used
to read back `PRIVATE` visibility, `main` as the default and only branch, no
tags, AGPL-3.0 license detection, Issues enabled, and Wiki disabled.

The staging graph begins with one sanitized root commit and contains only
public-release follow-up commits. Every commit uses the maintainer's public
GitHub noreply identity; none of the private development history was pushed.
Gitleaks 8.30.1 scanned all reachable staging history with redacted output and
found no leaks.

The private GitHub workflows passed on the staged source:

- [Secret history scan](https://github.com/herman602/scribe/actions/runs/43803137324)
  checked every reachable commit with the pinned Gitleaks installer.
- [Quality](https://github.com/herman602/scribe/actions/runs/43803137515)
  passed locked installation, Ruff, formatting, strict mypy, 1,594 tests with
  branch coverage, explicit-target migrations, the public-tree scanner,
  wheel/sdist inspection, and installed-wheel smoke on Ubuntu and Python 3.12.

A separate fresh clone matched the staged commit and tree exactly, contained
no tags, and passed the public-tree scanner. GitHub's generated source archive
contained 379 files and also produced zero findings when every extracted file
was scanned. GitHub's own GFM endpoint rendered the README and installation
guide successfully, and the bug report, parser request, and issue-template
configuration files were present through the repository API.

This audit update is itself a source change. Its successor commit must receive
